# ADR-0003: 신청 데이터는 스키마리스 JSON 컬럼에 저장한다

## 상태
Accepted

## 맥락
신청 폼은 운영자가 등록한 HTML(AI가 생성)에 정의되어 있고, 필드명은 캠페인마다 다를 수 있다.
"관계형 데이터베이스를 사용해 주세요"라는 제약은 있지만, 신청 폼 필드 스키마를 사전에 알 수
없다.

## 결정
Submission.data를 고정 컬럼이 아니라 JSON(PostgreSQL jsonb) 컬럼에 저장한다. 폼 필드
key-value 전체를 그대로 담는다. 직렬화/역직렬화는 애플리케이션 레이어에서 처리한다.

## 근거
- 고정 컬럼으로 모델링하려면 폼 필드 스키마를 사전에 정의해야 하는데, 이는 사실상 범용 폼
  빌더를 만드는 것과 같아져 스코프를 벗어난다.
- jsonb 컬럼은 관계형 DB(PostgreSQL)의 정식 컬럼 타입이므로 "관계형 데이터베이스 사용"
  요구사항과 배치되지 않는다. Campaign, Visit 등 다른 엔티티와의 FK 관계는 정규 컬럼으로
  유지한다.

## 결과
- 장점: 임의의 HTML 폼 필드를 스키마 변경 없이 수용할 수 있다.
- 단점: 필드별 통계(예: 특정 필드 값 분포)를 SQL로 조회하려면 jsonb 연산자를 써야 하고,
  타입 안정성이 없다. 이번 과제의 성과 조회는 필드 값이 아니라 신청 건수 집계 위주라 영향이
  적다.

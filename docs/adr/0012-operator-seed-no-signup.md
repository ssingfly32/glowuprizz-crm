# ADR-0012: 운영자 계정은 회원가입 API 없이 시드 데이터로 제공한다

## 상태
Accepted

## 맥락
요구사항은 "인증한 운영자만 관리자 기능과 신청자 데이터를 볼 수 있어야 합니다"라고만 되어
있고, 운영자 계정을 어떻게 만드는지(회원가입 API, 초대, 수동 등록 등)는 명시하지 않았다.

## 결정
회원가입 API를 만들지 않는다. 대신 Flyway 마이그레이션(`V2__seed_operator.sql`)으로 데모용
운영자 계정 하나를 미리 등록해둔다 (email: `operator@glowuprizz.com`,
password: `glowup1234!`, README에 기재).

## 근거
- 과제 설명 어디에도 "운영자가 여러 명 가입한다"는 시나리오가 없다. 단일 조직 내부 도구라는
  ADR-0004의 가정과도 일치한다.
- 회원가입 API를 만들면 이메일 인증, 중복 가입 방지 같은 부가 로직까지 고려해야 하는데,
  "캠페인을 만들고 배포한 뒤 전환 데이터를 확인하는 흐름"이라는 과제의 핵심 목표와는
  무관하다.
- 평가자가 저장소를 받아 바로 로그인해서 흐름을 확인할 수 있어야 하므로, 시드 계정이
  회원가입 화면을 거치는 것보다 더 빠르고 확실하다.

## 결과
- 장점: 로그인 API(POST /admin/auth/login) 구현/테스트에만 집중할 수 있다.
- 단점: 실제 서비스라면 운영자 계정 관리(초대, 비밀번호 재설정 등)가 반드시 필요하다.
  이번 스코프에서는 명시적으로 범위 밖으로 남긴다.

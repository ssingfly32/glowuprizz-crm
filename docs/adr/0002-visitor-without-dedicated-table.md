# ADR-0002: Visitor는 별도 테이블 없이 익명 쿠키 토큰으로 대체한다

## 상태
Accepted

## 맥락
"캠페인별 방문, 방문자, 신청, 전환율을 확인할 수 있어야 합니다"라는 요구사항을 충족하려면
"방문(visit)"과 "방문자(visitor, 순 방문자 수)"를 구분해서 집계해야 한다. 방문자는 로그인하지
않는 익명 사용자다.

## 결정
Visitor 엔티티/테이블을 따로 두지 않는다. 첫 방문 시 발급하는 익명 쿠키 값(visitorToken)을
Visit, Submission 로우에 직접 저장한다. "방문 수" = COUNT(*), "방문자 수" =
COUNT(DISTINCT visitor_token)으로 집계한다.

## 근거
- 별도 Visitor 테이블은 "이 토큰을 가진 사람이 누구인지"에 대한 추가 정보(예: 프로필,
  여러 캠페인 간 통합 식별)가 필요할 때 의미가 있는데, 이번 과제 범위에는 그런 요구사항이 없다.
- 쿠키 토큰만으로 방문/방문자 집계 요구사항은 전부 충족 가능하다.

## 결과
- 장점: 테이블과 조인이 하나 줄어든다.
- 단점: 쿠키를 삭제하거나 다른 브라우저로 접속하면 동일인이 다른 방문자로 집계된다. 이는 익명
  트래킹의 일반적인 한계로, 실제 서비스라면 동일한 한계를 갖는다.

# ADR-0013: 채널별 성과는 캠페인 하위 리소스로 스코프하고, 순 방문자 0명일 때 전환율은 0으로 처리한다

## 상태
Accepted

## 맥락
요구사항 "운영자는 캠페인별 방문, 방문자, 신청, 전환율과 채널별 성과를 확인합니다"는 두 가지를
분리해서 읽을 수 있다.

1. 채널별 성과를 캠페인 하나의 하위 지표로 볼 것인가 (이 캠페인 안에서 인스타그램 vs X 성과 비교)
2. 아니면 전체 캠페인을 가로지르는 전역 채널 지표로 볼 것인가 (전체적으로 어느 채널이 잘 되는가)

또한 ADR-0006(전환율 = 신청 수 / 순 방문자 수)에서 분모가 0일 때의 처리를 별도 결정으로
남겨뒀었다.

## 결정
1. **스코프**: `GET /admin/campaigns/{campaignId}/stats` 하나의 엔드포인트에서 캠페인 전체
   합계와 채널별 breakdown(`channels` 배열)을 함께 반환한다. 별도의 전역 채널 통계 엔드포인트는
   만들지 않는다.
2. **0 분모 처리**: 순 방문자 수가 0이면 전환율은 (정의상 계산 불가능하지만) `0`으로 반환한다.
   `NaN`이나 예외를 던지지 않는다.
3. **반올림**: 전환율은 소수 넷째 자리로 반올림한다.
4. **채널 목록**: 항상 4개 채널(INSTAGRAM/X/YOUTUBE/THREADS)을 반환하지 않고, 해당 캠페인에서
   방문 또는 신청이 실제로 1건 이상 발생한 채널만 `channels` 배열에 포함한다. 링크만 만들고
   아직 방문이 없는 채널은 포함하지 않는다.

## 근거
1. 운영자의 실제 작업 흐름은 "이 캠페인의 관리자 화면에서 채널별 성과를 본다"이다
   (요구사항 원문이 "운영자는 관리자 화면에서 캠페인별 ... 채널별 성과를 확인합니다"라고
   캠페인 문맥 안에서 서술됨). 배포 링크(DistributionLink)도 캠페인에 종속된 리소스이므로
   채널 성과 역시 캠페인 하위로 스코프하는 것이 도메인 모델과 일관적이다.
   전체 캠페인 가로지르는 채널 비교는 이번 과제 스코프 밖으로 판단한다.
2. 전환율 계산에서 분모가 0인 경우 예외를 던지면 "방문이 아직 없는 신규 캠페인"이라는 정상
   상태에서 관리자 화면 API 호출이 실패하게 된다. 0으로 처리하는 편이 프론트엔드 구현이
   단순해진다.
3. 채널 목록을 실제 데이터가 있는 채널로만 제한하는 이유: `DistributionLink` 생성만으로는
   성과가 없으므로(ADR-0005: 링크 개수와 무관하게 채널 컬럼 기준 GROUP BY), 링크 존재 여부가
   아니라 실제 방문/신청 로우 존재 여부를 기준으로 삼는 것이 "성과"라는 이름에 더 부합한다.

## 결과
- 장점: 엔드포인트 하나로 캠페인 화면에 필요한 지표를 모두 채운다. 프론트엔드가 조인할 필요가
  없다.
- 단점: "여러 캠페인을 합쳐 어느 채널이 제일 좋은가"를 보려면 캠페인별로 API를 여러 번 호출해
  클라이언트에서 합산해야 한다. 필요해지면 `GET /admin/channels/stats` 같은 전역 집계
  엔드포인트를 별도로 추가하면 된다 (현재 스코프에서는 생략).

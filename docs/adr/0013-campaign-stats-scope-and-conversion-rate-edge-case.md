# ADR-0013: 캠페인 하위 채널 breakdown과 전역 채널 성과를 모두 제공하고, 순 방문자 0명일 때 전환율은 0으로 처리한다

## 상태
Accepted (2026-09-12 개정: 최초 버전에서 생략했던 전역 채널 성과 엔드포인트를 추가)

## 맥락
기능 요구사항은 아래 두 항목을 별개의 문장으로 명시한다.

> - 운영자는 캠페인별 방문, 방문자, 신청, 전환율을 확인할 수 있어야 합니다.
> - 운영자는 채널별 성과를 확인할 수 있어야 합니다.

이 문서의 최초 버전은 개요의 요약 문장("캠페인별 ... 과 채널별 성과를 확인합니다")을 근거로
두 항목을 하나로 합쳐, 캠페인 하위 스코프의 채널 breakdown만 구현하고 전역 채널 성과
엔드포인트는 "필요해지면 추가" 항목으로 미뤄뒀었다. 다시 검토한 결과, 기능 요구사항 목록에서
두 항목이 별도 bullet로 분리돼 있는 것은 "이 캠페인 안에서 채널 비교"와 "전체 캠페인을
가로지르는 채널 비교"라는 서로 다른 두 가지 조회 니즈를 가리키는 것으로 읽는 편이 더
합리적이라고 판단해 전역 엔드포인트를 추가로 구현한다.

또한 ADR-0006(전환율 = 신청 수 / 순 방문자 수)에서 분모가 0일 때의 처리를 별도 결정으로
남겨뒀었다.

## 결정
1. **스코프**: 두 엔드포인트를 모두 제공한다.
   - `GET /admin/campaigns/{campaignId}/stats`: 캠페인 하나의 전체 합계와 그 캠페인 안에서의
     채널별 breakdown(`channels` 배열)을 함께 반환한다.
   - `GET /admin/channels/stats`: 모든 캠페인을 가로질러 채널 기준으로 합산한 전역 성과를
     배열로 반환한다.
   - 두 엔드포인트는 채널 병합 로직(`ChannelStatsMerger`)을 공유하고, 집계 기준(캠페인
     필터 유무)만 다르다.
2. **0 분모 처리**: 순 방문자 수가 0이면 전환율은 (정의상 계산 불가능하지만) `0`으로 반환한다.
   `NaN`이나 예외를 던지지 않는다.
3. **반올림**: 전환율은 소수 넷째 자리로 반올림한다.
4. **채널 목록**: 항상 4개 채널(INSTAGRAM/X/YOUTUBE/THREADS)을 반환하지 않고, 방문 또는
   신청이 실제로 1건 이상 발생한 채널만 포함한다 (캠페인 하위/전역 모두 동일). 링크만 만들고
   아직 방문이 없는 채널은 포함하지 않는다.

## 근거
1. 캠페인 하위 breakdown은 "이 캠페인의 관리자 화면에서 채널별 성과를 본다"는 작업 흐름에
   대응한다. 배포 링크(DistributionLink)도 캠페인에 종속된 리소스이므로 도메인 모델과도
   일관적이다.
   전역 엔드포인트는 "전체적으로 어느 채널이 잘 되는가"라는, 캠페인 상세 화면과는 다른 별도
   조회 니즈(요구사항의 두 번째 bullet)에 대응한다. 이미 있는 채널 GROUP BY 쿼리에서
   `WHERE campaignId = :id` 조건만 빼면 되는 수준이라, 캠페인별 API를 여러 번 호출해
   클라이언트에서 직접 합산하게 하는 것보다 서버가 한 번에 답을 주는 편이 요구사항에도,
   구현 비용 대비로도 더 낫다고 판단했다.
2. 전환율 계산에서 분모가 0인 경우 예외를 던지면 "방문이 아직 없는 신규 캠페인"이라는 정상
   상태에서 관리자 화면 API 호출이 실패하게 된다. 0으로 처리하는 편이 프론트엔드 구현이
   단순해진다.
3. 채널 목록을 실제 데이터가 있는 채널로만 제한하는 이유: `DistributionLink` 생성만으로는
   성과가 없으므로(ADR-0005: 링크 개수와 무관하게 채널 컬럼 기준 GROUP BY), 링크 존재 여부가
   아니라 실제 방문/신청 로우 존재 여부를 기준으로 삼는 것이 "성과"라는 이름에 더 부합한다.

## 결과
- 장점: 캠페인 상세 화면과 전체 채널 비교 화면 모두 클라이언트 쪽 조인/합산 없이 서버 응답
  하나로 채울 수 있다.
- 단점: 전역 엔드포인트는 운영자별/기간별 필터가 없어, "이번 달만" 같은 조회는 아직 지원하지
  않는다. 필요해지면 쿼리 파라미터로 확장하면 된다 (현재 스코프에서는 생략).
